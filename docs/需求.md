# 需求文档：登录与注册

## 1. 目标

为 ai-admin 后台提供最基础的账号体系：用户可以用用户名和密码注册、登录、退出，未登录用户无法访问后台页面。

## 2. 范围

**包含**

- 用户名 + 密码注册
- 用户名 + 密码登录
- 退出登录
- 登录状态保持与受保护页面拦截

**不包含（后续迭代）**

- 邮箱、手机号登录，以及第三方登录（GitHub、Google 等）
- 找回 / 重置密码
- 角色与权限管理
- 验证码、登录失败锁定

## 3. 功能需求

### 3.1 注册

| 字段 | 规则 |
| --- | --- |
| 用户名 | 必填，3–20 个字符，只能包含字母、数字和下划线，系统内唯一（不区分大小写） |
| 密码 | 必填，至少 8 个字符 |

- 校验不通过时，在对应输入框下方显示错误提示，不提交请求。
- 用户名已被注册时，提示「该用户名已被注册」。
- 注册成功后自动登录，并跳转到 `/dashboard`。

### 3.2 登录

| 字段 | 规则 |
| --- | --- |
| 用户名 | 必填 |
| 密码 | 必填 |

- 用户名或密码错误时，统一提示「用户名或密码错误」，不区分具体是哪一项错误。
- 登录成功后跳转到 `/dashboard`。
- 已登录用户访问 `/login` 时，直接跳转到 `/dashboard`。

### 3.3 退出登录

- 页面右上角的用户菜单显示当前用户名，并提供「退出登录」。
- 退出后清除会话，跳转到 `/login`。

### 3.4 访问控制

- 未登录用户访问 `/dashboard` 等受保护页面时，重定向到 `/login`。
- 需要登录的接口使用 `protectedProcedure`，未登录时返回 `UNAUTHORIZED`。

## 4. 页面

| 路径 | 说明 |
| --- | --- |
| `/login` | 登录 / 注册页，两个表单可互相切换，默认显示登录 |
| `/dashboard` | 登录后的首页，显示「欢迎，{用户名}」 |

## 5. 交互要求

- 提交过程中禁用按钮，并显示「提交中...」。
- 操作成功或失败时，使用 toast 提示结果。
- 表单支持回车提交，输入框都有对应的 label。

## 6. 非功能要求

- 密码由 Better Auth 加密存储，任何接口都不返回密码。
- 会话 cookie 设置 `httpOnly` 和 `secure`，跨域请求需在 `CORS_ORIGIN` 白名单内。
- 移动端（Expo）复用同一套接口，会话保存在 SecureStore 中。

## 7. 实现说明

- 使用 Better Auth 的 `username` 插件，服务端和客户端（web、native）都要注册该插件；修改后运行 `pnpm auth:generate` 和 `pnpm db:migrate`，为 `User` 表增加 `username` 字段。
- Better Auth 的 `User` 表要求 `email` 字段必填且唯一。注册时由前端按用户名生成一个内部占位邮箱（如 `{username}@users.ai-admin.local`），不在界面展示，也不用于登录。
- 关闭邮箱登录入口，只保留 `signIn.username` 和 `signUp.email`（附带 `username` 字段）。

## 8. 验收标准

- [ ] 使用新用户名注册成功后自动进入 `/dashboard`，页面显示该用户名。
- [ ] 使用已注册的用户名（包括仅大小写不同的）再次注册，提示「该用户名已被注册」。
- [ ] 使用错误的密码登录，提示「用户名或密码错误」。
- [ ] 未登录时直接访问 `/dashboard`，被重定向到 `/login`。
- [ ] 退出登录后再访问 `/dashboard`，被重定向到 `/login`。
- [ ] 刷新页面后仍保持登录状态。
